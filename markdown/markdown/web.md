## 深入探讨
    
1. 在前端浏览器与数据库之间，处理数据，进行业务逻辑处理
2. ==接收，处理，执行指令==,后端服务器连接数据库,管理数据库
3. 接收前端请求，返回数据给前端
4. ==效率更高==，前后端混合，代码杂乱，不好维护，前后端分离，任务分工明确，效率高
5. ==解决问题==
    混合开发，前后端相互等待，前后端代码相互影响
    使用不同语言，技术开发
    分工明确，职责单一，易于维护，找出问题
6. API接口契约，提前定义好接口的数据格式和规范，相当于双方有了规定，必须遵守。
    在前端调用api，发送api请求给后端，后端返回api响应
7. C语言，java，python都可以用作后端开发，实现web的功能，只是优势不同。
    -python轻量化，快速实现
    -java稳定，流程规范，适合企业大规模使用开发

## 题目任务
1. 基础理解
    1. web前端：发生在客户端，接收用户操作指令，并传给后端（从客户端->服务端） 例：b站点击视
    频一键三连，发送至服务端
    2. web后端：发生在服务端，接收前端请求，处理后连接数据库执行请求，再返回结果（服务端->
    客户端） 例:向数据库插入一键三连的记录，扣除硬币。。。
2. 后端深度 后端开发层层深入。接收请求/返回响应，处理请求，连接数据库并执行请求的过程靠编程语言实现。
    接收到请求后根据请求类型执行不同语句（post/get...），返回数据
    跳入处理类，对请求进行处理，处理数据
    进入接口，连接数据库，传入处理后的请求，获取数据，返回处理类
3. 架构分析
    1. 优点
    提升效率
    优化维护
    后端语言独立选择，不与前端绑定
    1后端API可同时服务不同前端
    2. 问题
    需要向后端请求，再返回数据，需要时间，可能无法加载出数据
    前后分离，团队可能沟通不好，导致接口理解不同，降低效率
    API设计不好，导致前后端无法连接
    4. 个人规划 个人认为web后端的规划流程规范优美，思路清晰（IDEA好玩），喜欢流程化的代码。 后端开
